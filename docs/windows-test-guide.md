## 0.2.1 권한 제한 감지·자동 메뉴·첫 메뉴 테스트

- 일반 권한으로 차곡을 켠 뒤 대상 프로그램을 새로 실행하고 2초 이상 유지한 후 종료합니다. WMI가 거부되는 환경에서는 ‘대체 감지’ 기록과 오류 단계·코드를 확인하고 시작·종료 규칙이 각각 한 번만 실행되는지 확인합니다. 이미 켜진 프로그램은 시작으로 처리하면 안 됩니다.
- 같은 EXE를 여러 개 실행해 첫 시작·마지막 종료만 요청을 만드는지 확인합니다. 같은 이름의 다른 경로 EXE는 제외되어야 합니다. 관리자·보호된 프로세스의 경로를 못 읽을 때 종료 요청을 만들면 안 됩니다. WMI 감지 권한이 있는 환경에서는 기존 이벤트 방식도 재검증합니다.
- 대체 감지 중 프로그램 경로·사용 여부·폴더 조건 변경·감지 일시 중지·앱 종료로 이전 확인 루프가 남지 않아야 합니다. 짧은 실행과 표본 사이 재시작 누락은 대체 방식의 한계로 구분합니다.
- 시작 시 기존 메뉴가 없으면 등록하고 경로가 같으면 재등록하지 않는지 확인합니다. EXE 이동 후 경로 갱신, 자동 등록 끄기·재시작, 메뉴 해제 후 설정 취소·재시작을 확인합니다. 해제한 메뉴를 자동으로 되살리면 안 됩니다.
- 개발자 모드가 꺼진 일반 PC에서 첫 메뉴 설치를 시도하지 않고 기존 메뉴를 유지해야 합니다. 차곡이 개발자 모드·인증서 신뢰·관리자 설정을 바꾸면 안 됩니다.
- x64 Windows 11 테스트 PC에서 사용자가 개발자 모드를 켠 뒤 메뉴 등록을 실행합니다. 첫 메뉴의 ‘차곡에 추가’ 이름·아이콘·한 폴더 선택 상태·실제 규칙 추가 창을 확인합니다. 한글·공백·&·쉼표·작은따옴표가 있는 EXE와 폴더 경로를 확인합니다. 등록 오류가 있으면 HRESULT와 출력 메시지를 보존합니다. 필요하면 탐색기 다시 열기 또는 재로그인 후 확인합니다.
- 재시작 시 이미 같은 패키지·경로면 재설치하지 않아야 합니다. EXE 이동·업데이트 후 경로 갱신과 옛 DLL 로딩 상태를 확인합니다. 첫 메뉴와 기존 메뉴 해제, 해제 실패 안내, 등록 중 시간 제한·설정 잠금도 확인합니다. 연동 캐시는 파일 검사에서 제외되어야 합니다.
- 실제 Windows의 개발자 등록·COM 활성화·메뉴 표시·권한·프로세스 API·트레이·배율은 macOS의 빌드·정적 확인과 구분해서 기록합니다.

## 0.2.0 폴더 복제·폴더 조건·탐색기 연동

- 이전 설정으로 시작하면 폴더 실행 조건이 수동으로 표시되고 기존 규칙이 그대로 동작해야 합니다. 폴더 목록의 복제 버튼을 눌러 설정·모든 규칙이 채워졌는지 확인합니다. 새 이름·검사 경로로 복제하고 원본 보존, 규칙 순서·사용 여부·목적지 유지, 제외 경로 재배치를 확인합니다. 취소·겹치는 경로 거부·경로를 여러 번 수정한 뒤 제외 추가도 확인합니다.
- 폴더 설정에서 프로그램 실행·종료와 확인/자동 처리를 저장합니다. Windows 기본 .exe 선택, 취소 시 입력 보존, 재실행 후 유지, 메인 폴더 조건 표시를 확인합니다. 같은 프로그램의 다중 실행본은 첫 시작·마지막 종료만 감지해야 합니다.
- 폴더 조건만 일치하면 켜진 규칙 전체를 순서대로 검사해야 합니다. 규칙의 파일명·확장자·제외·하위 폴더 설정을 함께 확인합니다. 폴더와 규칙 조건이 모두 일치해도 한 목록·한 번만 실행해야 합니다. 확인/자동이 충돌하면 전체 목록을 확인 후 실행해야 합니다. 선행 규칙이 건너뛰기인 파일을 뒤 규칙이 대신 이동하면 안 됩니다.
- 폴더 조건과 다른 프로그램에 규칙 조건을 지정해 규칙 조건도 독립 동작하는지 확인합니다. 모든 규칙을 끄거나 감지를 일시 중지하면 요청이 생기면 안 됩니다.
- 설정에서 탐색기 메뉴 등록·재등록·해제와 즉시 적용을 확인합니다. 관리자 권한 없이 현재 사용자에게만 적용되고 차곡 메뉴 외에는 바뀌면 안 됩니다. Windows 11에서는 ‘더 많은 옵션 표시’ 또는 기존 메뉴에서 확인합니다. 한글·공백·&가 들어간 EXE 경로와 목적지 폴더로 테스트합니다.
- 앱 미실행 상태에서 ‘차곡에 추가’를 눌러 목적지가 채워지는지 확인합니다. 목적지 다시 선택, 기존 검사 폴더 선택, 새 검사 폴더 등록과 기존 규칙 편집을 확인합니다. 취소 또는 규칙 저장만으로 파일이 이동하면 안 됩니다. 새 검사 폴더 등록 후 규칙 취소 시 등록한 폴더는 유지되어야 합니다.
- 앱이 트레이에 실행 중일 때 같은 메뉴를 눌러 기존 앱이 열리는지 확인합니다. 검사·이동·다른 편집 창 사용 중에는 요청이 대기하고 작업이 끝난 뒤 열려야 합니다. 종료 요청 후 새 요청은 거부되어야 합니다. 요청 20개 제한과 존재하지 않는 폴더·링크 거부도 확인합니다.
- 이전 버전 실행 중 전달 실패 안내, EXE 이동 후 메뉴 경로 갱신, 읽기/쓰기 권한 제한 시 등록·해제 오류, 데이터 저장 실패 후 원본 설정 보존을 확인합니다. 라이트·다크·시스템 및 100%·150%·200% 배율에서 새 버튼·긴 경로·대화상자·스크롤을 확인합니다.

- 데이터 폴더 열기 실패는 설정 창 앞에 오류를 표시해야 합니다. 작은 창과 100%·150%·200% 배율에서 스크롤로 앱 정보·버튼에 접근할 수 있어야 합니다. 라이트·다크·시스템에서 아이콘·포커스·비활성을 확인합니다.

## 0.1.11 가로 테마 선택

- 메인 테마 버튼을 누르면 모니터·해·달 아이콘만 가로로 표시되어야 합니다. 호버 시 시스템·라이트·다크 툴팁과 현재 선택의 배경·테두리를 확인합니다.
- Tab·Enter/Space로 열고 Tab·방향키·Home·End로 이동한 뒤 Enter/Space로 선택합니다. Escape와 바깥 클릭은 설정을 바꾸지 않고 닫아야 합니다. 선택 후 메인 아이콘 버튼으로 포커스가 돌아와야 합니다.
- 재실행·설정 창 동기화, 저장 실패 시 이전 선택 복원, 작업 중 선택창 닫기·비활성, 검사 결과 보존을 확인합니다. 라이트·다크·시스템 및 100%·150%·200% 배율에서 확인합니다.

## 0.1.10 테마 아이콘

- 메인 화면에 콤보박스 대신 모니터·해·달 아이콘 버튼이 표시되는지 확인합니다. 클릭·Tab·Enter/Space로 메뉴를 열고, 방향키와 Enter로 선택하고 Escape로 닫습니다. 현재 테마 하나만 체크되어야 합니다.
- 시스템·라이트·다크를 바꾸면 아이콘·툴팁·설정 창이 함께 반영되고 재실행 후 유지되어야 합니다. 시스템 모드에서 Windows 테마를 바꿔도 시스템 아이콘은 모니터를 유지합니다.
- 설정 저장 실패 시 아이콘과 메뉴는 이전 선택으로 돌아와야 합니다. 검사·이동 중 버튼은 비활성이며 이미 열린 메뉴도 닫혀야 합니다. 테마 선택으로 현재 검사 결과를 지우지 않아야 합니다.
- 라이트·다크·시스템 및 100%·150%·200% 배율에서 아이콘·메뉴·포커스와 현재 선택 표시를 확인합니다.

## 0.1.9 설정·종료·규칙 카드

- 이전 버전 설정으로 시작해 창 닫기 기본값이 백그라운드 실행인지 확인합니다. X로 숨긴 뒤 트레이에서 다시 열었을 때 검사 결과가 유지되어야 합니다.
- 상단 ‘설정’에서 테마·창 닫기를 변경하고 저장·취소·다음 실행 후 유지 여부를 확인합니다. 상단 테마와 설정의 테마가 일치해야 합니다. 테마·닫기 설정만 바꿔도 현재 검사 결과·선택·완료 요약은 유지되어야 합니다.
- ‘프로그램 종료’로 설정하고 X를 누릅니다. 확인창 취소·Escape·X는 앱을 종료하지 않아야 합니다. ‘다시 묻지 않기’를 체크하고 취소해도 다음에는 확인창이 나와야 합니다.
- 확인창에서 ‘다시 묻지 않기’를 체크한 뒤 종료합니다. 다음 실행 후 X는 확인 없이 종료해야 합니다. 설정에서 ‘종료하기 전에 확인창 표시’를 다시 켜면 확인창이 복원되어야 합니다. 트레이 종료는 기존처럼 직접 종료를 요청합니다.
- 검사 중·큰 파일 이동 중 X로 종료를 요청합니다. 확인창을 여는 동안 작업이 끝나도 정상적으로 취소·종료를 선택할 수 있어야 합니다. 종료를 확정하면 새 감지 요청은 실행하지 않고 안전한 중단 후 종료해야 합니다. 이미 완료된 이동과 원본 보존 결과는 실제 파일 위치·기록으로 확인합니다.
- 종료 확인을 표시하는 동안 프로그램 시작·종료 이벤트를 발생시킵니다. 취소하면 대기 요청이 처리되고, 종료하면 새 작업을 시작하지 않아야 합니다. 같은 X를 여러 번 눌러 확인창이 중복으로 열리면 안 됩니다.
- 설정 파일을 저장할 수 없게 만든 테스트 환경에서 ‘다시 묻지 않기’와 설정 저장을 확인합니다. 오류를 표시하고 이전 값을 유지해야 하며 확인 생략 저장 실패로 앱이 종료되면 안 됩니다.
- 규칙 스위치의 켜짐·꺼짐·마우스 오버·키보드 포커스·작업 중 비활성 상태를 확인합니다. Tab으로 이동하고 Space로 반복 전환할 수 있어야 합니다. 꺼진 규칙은 편집 가능하고 검사 및 실행은 비활성이어야 합니다. 사용 여부 변경만으로 파일을 이동하지 않아야 합니다.
- 긴 규칙 이름·조건·경로와 900×640 창에서 제목·스위치·아래 버튼이 겹치지 않아야 합니다. 라이트·다크·시스템, 100%·150%·200% 배율에서 새 창과 카드를 확인합니다. 보조 기술에서 규칙 이름과 토글 상태를 구분할 수 있어야 합니다.

## 1-1. 0.1.8 진행과 결과 피드백

- 검사 시작 시 같은 화면에 검사 중 표시가 나오고, 검사만으로 파일을 이동했다고 표시하지 않는지 확인합니다. 검사 완료·취소·실패를 구분해야 합니다.

- 모두 성공하면 체크 표시와 정상 완료 제목·소요 시간이 남아야 합니다. 처리 결과 열에 파일별 상태가 있어야 하며 다른 페이지로 이동해도 유지되어야 합니다.

- 실행 전후로 취소를 눌러 취소된 시도와 미실행 개수를 확인합니다. 취소 전에 완료된 파일은 이동된 위치에 남아야 하며 ‘실행 취소’가 되돌리기라는 의미로 표시되면 안 됩니다.
- 목록·기록 쓰기 오류가 나면 오류 중단 요약과 이유가 남아야 합니다. 결과 저장에 문제가 생긴 경우 결과가 없는 행을 ‘미실행’으로 단정하지 않고 ‘미확인’으로 표시해야 합니다. 완료·취소·실패 뒤에는 막대가 계속 움직이거나 이전 파일의 알림이 결과 카드를 덮으면 안 됩니다.
- Windows의 애니메이션 효과를 끄고 완료 카드가 효과 없이 즉시 표시되는지 확인합니다. 켜면 짧게 한 번 강조되고 입력을 막지 않아야 합니다.
- 다크·라이트·시스템 모드에서 정상·주의·오류 글자와 막대가 읽히는지 확인합니다. 900×640 수준의 작은 창, 긴 파일명·긴 오류 메시지, 100%·150%·200% 배율에서 목록과 버튼이 가려지지 않는지 확인합니다.
- 완료 카드의 ‘기록 보기’로 이동할 수 있어야 합니다. 작업 중에는 페이지·선택·기록 이동이 잠기고 취소 버튼은 사용할 수 있어야 합니다.
- 키보드와 보조 기술로 진행률 이름과 종료 상태를 확인합니다. 종료 알림 때문에 포커스를 강제로 옮기지 않아야 합니다.

## 1-2. 0.1.7 대량 검사와 페이지 선택

- 테스트 복사본 250개 이상을 준비해 검사합니다. 첫 페이지는 100개, 마지막 페이지는 남은 항목만 표시하고 전체 개수와 페이지 번호가 맞는지 확인합니다.
- 첫 페이지의 항목 하나를 선택 해제하고 다음 페이지로 이동한 뒤 돌아옵니다. 선택 해제가 유지되고 ‘선택 N개 실행’ 수치가 전체 결과 기준인지 확인합니다.
- 전체 선택 해제 후 첫 페이지와 마지막 페이지에서 각각 하나만 선택합니다. 두 항목만 이동하고 다른 항목은 원본 위치에 남아야 합니다.
- 전체 선택은 현재 페이지 밖 항목에도 적용되어야 합니다. 실행 종료 뒤 페이지를 넘겨 볼 수 있지만 재실행은 새 검사 전까지 차단되어야 합니다.
- 개별 규칙 검사·폴더 전체 검사·프로그램 감지 후 확인·자동 실행 경로를 각각 확인합니다. 자동 실행에서도 첫 100건 이후 항목이 처리되어야 합니다.
- 검사 중 취소와 이동 중 취소를 각각 확인합니다. 설정 변경·다른 검사·규칙 목록 복귀·트레이 메뉴 종료 시 이전 임시 저장소가 정리되는지 확인합니다. 창 닫기는 숨기기이므로 현재 결과를 유지합니다.
- 복사본으로 실행 중 앱을 강제 종료한 뒤 재실행합니다. 오래된 검사가 자동 실행되지 않고 다음 검사 때 잔여 캐시가 정리되어야 합니다. 이미 이동한 파일은 실행 기록으로 확인합니다.
- 검사 결과 수를 늘리며 작업 관리자 메모리와 `%LOCALAPPDATA%\FileOrganizer\scan-cache`의 디스크 사용량을 함께 확인합니다. 이 변경은 앱 전체 메모리의 정확한 상한을 보장하지 않습니다.

## 2. 임시 데이터

빈 테스트 폴더를 하나 만들고 다음처럼 복사본을 준비합니다. 실제 보관 자료로 시작하지 마세요.

```text
FileOrganizer-Test/
  input/
    보고서_10월.txt
    보고서_최종.txt        ← 내용은 new로 저장
    메모.txt
    child/보고서_하위.txt
    excluded/보고서_제외.txt
  output/
    보고서_최종.txt        ← 내용은 old로 저장
```

검사 위치는 `input`, 이동 위치는 `output`, 파일명 포함 조건은 `보고서`, 확장자는 `.txt`로 설정합니다. `input/excluded`는 제외 폴더로 지정합니다.

## 3. 미리보기와 충돌 처리

각 경우마다 새 복사본으로 테스트합니다.

- 하위 폴더 포함을 끄면 최상위 보고서만 나타나는지 확인합니다.
- 포함을 켜면 `child`의 보고서가 추가되고 `excluded`와 `메모.txt`는 제외되는지 확인합니다.
- 미리보기만 실행한 뒤 원본과 대상이 그대로인지 확인합니다.
- 상단 `폴더 전체 검사 및 실행`은 켜진 규칙 전체, 각 규칙의 `검사 및 실행`은 해당 규칙 하나만 검사해야 합니다. 검사 결과 화면에 적용 범위가 표시되어야 합니다. 두 경로 모두 별도의 실행 버튼을 누르기 전까지 파일을 옮기지 않아야 합니다.
- `이름 변경 후 이동`: 기존 `보고서_최종.txt`와 새 `보고서_최종 (1).txt`가 모두 남아야 합니다.
- `건너뛰기`: 원본·기존 대상이 모두 그대로이고 미리보기에서 실행할 수 없어야 합니다.
- `교체`: 대상의 내용은 new, 기존 old 파일은 휴지통에 있어야 합니다. 휴지통 이동에 실패하면 교체를 중단해야 합니다.
- 항목 하나를 선택 해제하면 그 파일은 원래 위치에 남아야 합니다.
- 실행 기록에서 원본·대상·규칙·결과·설명이 실제 결과와 일치하는지 확인합니다.
- 다시 미리보기한 뒤 원본이나 기존 대상의 내용을 바꾸면 기존 계획으로 이동·교체하지 않아야 합니다.

## 4. 다른 드라이브와 실패 처리

- 테스트 복사본을 `C:`에서 `D:` 또는 외장 드라이브로 옮깁니다. 이동 후 파일 내용과 원본 제거를 확인합니다.
- 이동 폴더 자동 생성을 켜고 존재하지 않는 폴더 경로를 입력합니다. 실행 후 폴더와 파일이 생겨야 합니다.
- 자동 생성을 끄면 없는 대상 폴더에 대한 항목은 보류되어야 합니다.
- 프로그램이 파일을 쓰는 동안 실행하면 원본을 잃지 않고 실패·보류되어야 합니다.
- 이동 시작 전 외장 드라이브를 분리하면 원본이 남고 실패 이유가 기록되어야 합니다.
- 큰 테스트 파일을 이동하다 취소하고 원본 또는 검증된 대상 사본이 남는지 확인합니다. 불완전한 임시 파일이 최종 파일명으로 남으면 안 됩니다.
- 이름이 같은 여러 파일을 서로 다른 하위 폴더에 넣어, 미리보기의 번호와 실제 이동 결과가 일치하는지 확인합니다.

## 5. 프로그램 감지와 트레이

- 실제 실행 파일의 전체 경로를 알 수 있고 몇 초 이상 실행되는 프로그램을 선택합니다.
- 감지 후 `목록 확인`을 선택합니다. 대상 프로그램을 실행·종료하면 요청이 표시되고 확인 전에는 파일을 옮기지 않아야 합니다.
- 시작 조건은 첫 실행본 시작 때, 종료 조건은 같은 경로의 마지막 실행본 종료 때 한 번 발생해야 합니다.
- 자동 실행 옵션도 새 테스트 복사본으로 확인합니다.
- 규칙 편집 중 감지된 요청은 편집을 방해하지 않고 대기해야 합니다.
- 창을 닫아 트레이에 남긴 뒤에도 감지되어야 합니다. 트레이의 일시 중지를 켜면 새 요청을 만들지 않아야 합니다.
- 트레이에서 완전히 종료하면 감지도 멈춰야 합니다.

## 문제 보고

문제가 생기면 적용 규칙, 실제 원본·대상 상태, 발생 시간, 오류 메시지와 `%LOCALAPPDATA%\FileOrganizer\history.jsonl`의 관련 줄을 전달하면 됩니다. 기록을 공유할 때 개인 경로는 가려도 됩니다.

## 0.2.2 재확인

1. 기존 앱을 트레이에서 완전히 종료한 뒤 0.2.2를 실행합니다. 설정의 실제 버전을 확인합니다.
2. ‘차곡에 추가’에서 이름이 서로 다른 검사 폴더를 선택합니다. 닫힌 콤보박스에는 폴더 이름, 아래에는 해당 전체 경로가 보여야 합니다. 드롭다운·키보드 선택·라이트·다크·시스템·125/150% 배율을 확인합니다. `FileOrganizer.Core.FolderSpec`가 보이면 실패입니다.
3. 개발자 모드가 이미 켜진 x64 Windows 11에서 설정의 메뉴 등록을 누릅니다. `Chagok.AddRule` 관련 0x80080204가 없어야 합니다. 첫 메뉴의 ‘차곡에 추가’가 정확한 목적지를 전달하는지 확인합니다. 실제 Appx 스키마·COM 로딩은 Windows에서 확인해야 합니다.
4. 자동 실행 조건을 실제로 오래 실행되는 EXE에 지정합니다. 편집 창과 확인 목록을 닫은 상태에서 트레이로 숨깁니다. 파일 복사본을 매번 새로 준비해 실행→종료→재실행을 5회 반복합니다. 1초 미만의 종료 간격에서도 새 실행이 250ms 이상 관측되면 각 실행이 기록돼야 합니다. 시작·종료 조건은 각각 따로 확인합니다.
5. 같은 EXE 두 실행본이 겹치면 추가 실행·중간 종료를 알리지 않고 마지막 종료만 알리는지 확인합니다. 단일 인스턴스 앱의 창 열기와 새 프로세스 시작은 다릅니다. 잔류 프로세스·런처가 있는 앱은 작업 관리자에서 실제 EXE를 확인합니다.
6. 편집 창·수동 검사 확인 목록을 열어 놓고 감지합니다. 실행 기록의 ‘감지됨’에 대기 이유가 있어야 하며 확인 전 파일을 옮기면 안 됩니다. 대기 해제 후 기존 요청이 처리되는지 확인합니다.
7. 계속 누락되면 감지 대상 EXE 경로, 시작/종료 조건, 자동/확인 모드, 발생 시간과 history.jsonl의 ‘대체 감지’·‘감지됨’·‘경로 확인’·실패 기록을 함께 확인합니다. 250ms 사이에 끝난 실행과 PID가 관측되지 않은 재사용은 이 방식의 한계입니다.


## 0.5.1 TUI 선택 범위

- 선택 배경은 현재 조작 중인 패널의 내용 칸 안에서 끝나야 한다. 테두리·좌우 간격·반대 패널에 번지지 않는다.
- 반대쪽 선택은 ·와 글자색으로 유지한다. 이름에 >가 있어도 강조하지 않는다. 좁은 창/긴 한글 이름/NO_COLOR/미리보기도 확인한다.


## 0.5.2 도트 이름

- TUI 상단 CHAGOK가 D안 점 문자로 보이는지, 60/80/110열에서 잘리지 않는지 확인. 배너 뒤 색 복원과 NO_COLOR도 확인.


## 0.5.3 TUI 상세보기

- I는 현재 영역에 따라 폴더/규칙 상세를 표시한다. 일반 오류 Notice로 상세를 출력하지 않는다.
- 항목 이름과 값을 분리하고 긴 경로를 셀 폭 기준으로 줄바꿈한다. 스크롤·목록 복귀 뒤 설정과 선택을 보존한다.


## 0.5.4 TUI 입력 화면

- 폴더/규칙 폼은 같은 테두리·섹션을 사용하고 입력 단계마다 다시 그린다. 현재 값·번호 선택지·검사 폴더 문맥·최근 입력을 표시한다.
- 저장 전 전체 내용 스크롤과 Y 저장/취소를 유지한다. 폼 입력은 지정 행 안에서 편집하되 커서 위치 조회에 의존하지 않는다. 긴 경로·한글·Esc/취소/Enter 기존 값 보존을 실제 PTY로 확인한다.


## 0.5.5 선택형 설정

- 설정은 네 항목을 한 화면에 표시하고 원하는 항목을 바로 선택한다. 변경 값은 임시 복사본에만 반영, S 저장과 Esc 취소를 구분한다.
- ↑↓/Tab/1~4 선택, ←→/Enter/Space 변경. 선택 설명·미저장 표시·도움말 왕복·60열 화면·저장 실패 시 재시도를 확인한다. GUI 전용 설정과 TUI 팔레트/실제 탐색기 등록을 구분한다.


## 0.5.6 폴더·규칙 목록형 폼

- 폴더/규칙/복제 폼은 항목을 직접 선택한다. 조건상 비활성인 항목은 값을 보존하고 편집을 막는다.
- 입력창 취소와 전체 폼 취소를 구분한다. S 검토 후 Y 저장, 검토 취소/저장 검증 실패는 초안을 유지한다.
- 경로 변경 시 제외 폴더 재배치는 현재 편집 경로를 기준으로 수행한다. 항목 수정 순서와 관계없이 복제/ID/규칙/검사 안전성을 유지한다.
- 작은 창 선택 행 자동 스크롤·I 전체 값·다른 항목 우선 편집·설정 보존을 실제 PTY로 확인한다.
