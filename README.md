# 차곡 · CHAGOK — 0.5.8 테스트 빌드

**[차곡 0.5.8 다운로드 · Windows x64](https://github.com/ksyrang/Chagok/releases/tag/v0.5.8)**

릴리스 페이지에서 `Chagok-v0.5.8-win-x64.zip`을 내려받아 압축을 푼 뒤 `Chagok-v0.5.8.exe`를 실행하세요. 현재는 서명하지 않은 테스트 빌드입니다.

ksyrang이 개발하는 차곡은 폴더별 규칙으로 파일을 정리하는 Windows 도구입니다. 폴더·규칙 중심의 구성은 [Forel](https://github.com/lab421/forel)에서 영감을 받았습니다. Forel 또는 lab421의 공식·제휴 프로젝트는 아닙니다.

[Forel 참조 범위와 출처 점검 기록](docs/forel-provenance-review.md)

[사용 설명서 (HTML)](사용설명서.html) — 4단계 화면 예시와 핵심 순서 그림으로 안내합니다. 자세한 내용은 펼쳐 읽을 수 있으며, 인터넷 없이 열기·문서 테마·인쇄/PDF 저장을 제공합니다.

## 0.5.8 이동 위치 표시·항목 설명

- 최근 이동 위치 표시를 켜면 새 규칙의 이동할 폴더에 가장 최근 기본 위치를 미리 채웁니다. 최근 위치 콤보박스는 유지합니다. 기존 규칙 편집과 탐색기에서 지정한 목적지는 그대로 유지합니다.
- ‘규칙명 폴더 사용’을 켜면 GUI의 ‘이동할 폴더’ 입력칸에 규칙명이 붙은 최종 경로를 표시합니다. 아래 기본 위치를 수정하거나 찾아보기·최근 위치를 선택하면 최종 경로도 즉시 갱신합니다. 끄면 기본 경로 입력으로 돌아갑니다.
- TUI 폴더·규칙의 선택 항목 아래에 기능과 연계 옵션을 설명합니다. I는 전체 값과 설명을 스크롤해 보여줍니다. 규칙명 폴더 사용 시 자동 생성은 ‘켜짐 · 자동 적용’으로 표시하고 변경할 수 없는 이유를 설명합니다.

## 이동 위치 도우미

- 검사 폴더 설정의 ‘규칙에서 최근 사용한 이동 위치 표시’를 켜면 해당 폴더의 규칙을 저장할 때 기본 이동 위치를 최근 10개까지 기록합니다. 규칙 입력에서 선택할 수 있습니다. 기본값은 꺼짐입니다. 끄면 표시·새 기록을 중단하고 기존 기록은 유지합니다.
- 규칙 이름 아래 ‘규칙명 폴더 사용’을 켜면 `선택한 기본 위치\규칙명`으로 이동합니다. 예: `D:\정리` + `PDF` → `D:\정리\PDF`. 최종 이동 폴더를 확인한 뒤 저장하세요.
- 규칙명 폴더는 실제 실행 때 자동 생성합니다. 규칙명을 바꾸면 다음 검사의 이동 경로도 바뀝니다. 이미 이동한 파일은 다시 옮기지 않습니다. 옵션을 끄면 기존 자동 생성 설정을 따릅니다.
- TUI도 폴더·규칙 입력 항목에서 같은 옵션을 제공합니다. 최근 위치는 ←→로 선택하고 최종 경로는 I로 확인합니다. CLI는 `folders add/update --recent-destinations on|off`, `rules add/update --append-rule-name on|off`를 제공합니다.

상단 다운로드 링크에서 0.5.8 사전 릴리스와 ZIP 무결성 확인용 SHA256 파일을 받을 수 있습니다. 새 옵션을 저장한 설정을 이전 버전으로 편집하면 옵션이 유실될 수 있으므로 업데이트 전 설정을 백업하세요.

## 0.5.8 통합 실행·새 아이콘·TUI

`Chagok-v0.5.8.exe` 하나로 제공합니다. 더블 클릭은 GUI, PowerShell에서 `.\Chagok-v0.5.8.exe tui`는 TUI, `.\Chagok-v0.5.8.exe help`는 명령 도움말입니다. [터미널 사용법](docs/terminal-guide.md)을 확인하세요.

- GUI와 같은 폴더·규칙·앱 설정·기록을 사용합니다. JSON 버전 1과 기존 데이터 위치를 유지합니다.
- GUI·CLI·TUI 중 하나만 실행합니다. GUI가 트레이에 남아 있어도 거부됩니다. 기존 앱을 완전히 종료한 뒤 전환하세요.
- 폴더·규칙 관리·복제, 검사·선택 실행·기록, Windows 프로그램 감지를 제공합니다. 수동 scan은 이동하지 않습니다.
- 자동화/JSON run은 `--yes`로 전체 실행 범위를 승인해야 합니다. 종료 코드로 성공·부분 처리·오류·사용 중을 구분합니다.
- 경로는 터미널에서 입력합니다. 트레이·탐색기 연동은 GUI에서 관리하며 watch/감지 화면이 실행 중일 때만 프로그램을 감지합니다.

TUI에서는 `F`로 폴더, `N`으로 선택 폴더의 규칙을 추가합니다. 저장한 항목은 즉시 선택합니다. 규칙 추가·편집 시작과 저장 확인에서 선택한 검사 폴더의 이름·전체 경로를 표시합니다. `Tab`으로 규칙 영역에 이동하고 `↑↓`로 규칙을 고른 뒤 `R`로 이 규칙만 검사 및 실행합니다. 미리보기에서 `Enter` → `Y`로 이동을 확정합니다. `A`는 폴더 전체 검사 및 실행입니다. TUI 상단의 차곡 심볼은 이미지 없이 문자로 표시합니다.

TUI 폴더·규칙 폼은 항목을 직접 골라 수정합니다. 입력창의 `Esc`/`/cancel`은 해당 항목만 취소하고, 항목 목록의 `Esc`는 폼 전체를 취소합니다. `S`로 검토한 뒤 `Y`로 저장합니다. 설정 화면은 `S` 저장, `Esc` 변경 취소입니다.

[TUI 문자·색 미리보기](docs/tui-preview.html) — 실제 터미널 출력에서 이름·경로를 예시로 바꾼 HTML입니다. Windows 표시와는 차이가 있을 수 있습니다.

## 기능 설명과 AI 사용

TUI의 메인/미리보기에서 F1 또는 ?로 기능 설명을 엽니다. 좌우로 기능을 바꾸고 위아래로 설명을 읽습니다. CLI는 `help run`, `rules add --help`, `help --json`을 제공합니다. 도움말은 설정·잠금을 열지 않아 다른 차곡이 실행 중이어도 읽을 수 있습니다.

[AI 사용 가이드](docs/agent-guide.md)와 [전체 CLI 명세 JSON](docs/cli-reference.json)을 함께 제공합니다. 명세에는 입력 형식·필수값·변경 효과·승인 조건·예시가 있습니다.

## 실행

1. `Chagok-v0.5.8-win-x64.zip`을 윈도우 PC의 쓰기 가능한 폴더에 압축 해제합니다.
2. `Chagok-v0.5.8.exe`를 실행합니다. 이 패키지는 일반 Intel/AMD 64비트 윈도우 PC용입니다.
3. 왼쪽 `＋`로 검사 폴더를 등록합니다.
4. `규칙 추가`에서 파일명·확장자, 이동 위치, 이름 충돌 처리, 실행 방식을 저장합니다.
5. 상단 `폴더 전체 검사 및 실행` 또는 각 규칙의 `검사 및 실행`을 누릅니다. 검사 결과에서 항목을 확인한 뒤 `선택 항목 실행`을 누릅니다. 검사 버튼만으로 파일을 이동하지 않습니다.

이전 버전을 사용했다면 트레이 메뉴에서 기존 앱을 완전히 종료한 뒤 새 실행 파일을 사용하세요. 폴더·규칙·테마 설정은 같은 저장 위치를 사용하므로 이어서 불러옵니다.

## 0.2.2 변경 사항

- 검사 폴더 콤보박스의 선택 영역에 내부 타입명 대신 폴더 이름을 표시하도록 공통 템플릿의 템플릿 선택기 연결을 복원했습니다. 아래 전체 경로는 보조 정보로 유지합니다.
- 첫 우클릭 메뉴 등록 실패 로그(0x80080204)의 Verb Id를 영숫자 `ChagokAddRule`로 수정했습니다. PowerShell 오류에는 진행 정보 XML 대신 예외 본문을 표시합니다.
- 대체 감지에서 표본 사이 기존 실행본이 모두 바뀌면 종료·재시작으로 구분합니다. 확인 간격은 250ms로 줄였으며 초기 상태는 감지 작업을 예약하기 전에 확보합니다. 표본 사이에 시작·종료가 모두 끝나는 실행은 여전히 놓칠 수 있습니다.
- 같은 파일명인데 실제 경로가 다른 프로세스는 ‘경로 확인’ 기록에 등록·실제 경로를 남깁니다. 파일명만 같다고 감지 대상으로 처리하지 않습니다.
- 감지 이벤트와 요청 추가·통합 개수, 편집 창·현재 작업·검사 목록 확인 때문에 대기하는 상태를 실행 기록에 남깁니다. 확인이 필요한 목록을 자동으로 실행하지 않습니다.

## 0.2.1 변경 사항

- WMI 감지 등록이 거부되면 감지를 중단하는 대신 1초 간격의 프로세스 확인으로 전환합니다. 실행 경로는 더 낮은 조회 권한의 QueryFullProcessImageName으로 읽습니다.
- 대체 감지에서 처음부터 실행 중인 프로그램은 시작으로 다시 알리지 않으며, 첫 실행본 시작·마지막 실행본 종료를 구분합니다. 경로 미확인·목록 조회 실패를 종료로 오인하지 않습니다. 1초보다 짧은 실행은 놓칠 수 있습니다.
- 차곡 시작 시 탐색기 메뉴를 확인하고 누락·EXE 경로 변경 시 등록·갱신합니다. 이미 같은 경로로 등록되어 있으면 다시 등록하지 않습니다. 설정에서 자동 확인을 끌 수 있고 메뉴 해제 시 자동 등록도 끄고 저장합니다.
- Windows 11 첫 우클릭 메뉴용 네이티브 확장과 테스트용 패키지를 EXE에 포함했습니다. x64 Windows 11의 개발자 모드에서만 테스트 등록합니다. 개발자 모드·인증서 신뢰·관리자 권한 설정을 자동으로 변경하지 않습니다. 일반 배포용 서명 패키지는 별도 준비가 필요합니다.

## 0.2.0 변경 사항

- 검사 폴더 목록의 복제 아이콘으로 폴더 설정과 규칙 전체를 복제합니다. 새 이름·검사 위치를 지정한 뒤 ‘복제’를 누릅니다. 원본은 유지하며 복제본은 새 ID를 사용합니다. 이동 목적지는 유지하고 제외 폴더는 새 검사 위치의 같은 하위 경로로 바꿉니다.
- 폴더 설정에 프로그램 실행·종료 조건을 추가했습니다. 폴더 조건이 맞으면 켜진 규칙 전체를 기존 순서로 검사합니다. 규칙 자체의 실행 조건도 독립적으로 동작합니다.
- 한 이벤트가 폴더와 규칙 조건에 모두 맞아도 한 목록으로 검사합니다. 두 경로 중 확인이 필요한 규칙이 있으면 폴더 목록 전체를 확인 후 실행합니다.
- ‘설정 → 탐색기 연동’에서 ‘차곡에 추가’ 메뉴를 등록·해제합니다. 우클릭한 폴더를 이동 목적지로 넣고 기존 검사 폴더 선택 또는 새 검사 폴더 등록 후 규칙을 만듭니다. 목적지도 다시 선택할 수 있습니다.
- 앱이 이미 실행 중이면 기존 창으로 요청을 전달합니다. 검사·이동·다른 창 사용 중 요청은 대기합니다. 우클릭만으로 파일을 이동하지 않습니다.

## 0.1.9 변경 사항

- 상단 ‘설정’에서 테마·창 닫기 동작·종료 전 확인을 저장할 수 있습니다. 기존 테마 빠른 선택도 유지합니다.
- 창 닫기를 백그라운드 실행 또는 프로그램 종료로 선택합니다. 기본값은 기존처럼 백그라운드 실행입니다.

- 규칙 카드의 ‘사용’ 체크박스를 켜짐/꺼짐 스위치로 바꿨습니다. 편집과 검사 및 실행을 카드 아래 오른쪽에 나란히 배치했습니다.
- 테마·닫기 설정만 변경할 때는 현재 검사 결과를 유지합니다. 기존 폴더·규칙·설정 저장 위치도 유지합니다.

## 처리 기준

- 규칙은 화면에 표시된 순서로 판단하며, 파일 하나는 처음 일치한 켜진 규칙 하나로만 처리합니다. 현재 버전은 규칙 추가 순서로 표시합니다.
- `폴더 전체 검사 및 실행`은 선택 폴더의 켜진 규칙 전체를 검사합니다. 각 규칙의 `검사 및 실행`은 해당 규칙만 검사합니다. 프로그램 감지 시에는 해당 실행 조건과 일치하는 규칙만 검사합니다.
- 실행 중 다른 실행 요청은 대기합니다. 같은 규칙의 반복 감지 요청은 대기 목록에서 합칩니다. 폴더·규칙 설정을 바꾸면 이전 대기 요청은 해제합니다. 테마·창 닫기 설정만 변경하면 유지합니다.
- 미리보기 뒤 폴더·규칙 설정이 바뀌거나 실행을 한 번 마치면 다시 검사해야 합니다. 실행 전에 원본·대상 파일 상태를 재확인하며, 변경되면 보류·실패로 기록합니다.
- 이름 충돌은 파일 내용과 관계없이 판단합니다. 같은 이름의 폴더가 대상 위치에 있으면 보류합니다.
- 이동은 임시 복사 → 무결성 검증 → 최종 위치 확정 → 원본 삭제 순서입니다. 같은 드라이브에서도 이 방식을 사용하므로 파일 크기만큼의 추가 공간이 필요합니다.
- 내부 무결성 검증은 복사 오류를 찾기 위한 것입니다. 내용이 같은 파일을 찾아 정리하는 기능은 아닙니다.
- 원본 삭제에 실패하거나 취소하면 대상 사본과 원본을 함께 보존할 수 있습니다. 실행 기록의 `원본 보존` 상태를 확인하세요.
- 기존 파일 교체는 윈도우 휴지통 API를 사용합니다. 휴지통 이동에 실패하면 영구 삭제로 재시도하지 않습니다. 교체 후 후속 단계가 실패한 경우 기존 파일은 휴지통에서 확인해야 합니다.
- 이동 폴더가 검사 폴더 안에 있으면 검사에서 제외합니다. 바로 가기·심볼릭 링크·연결 폴더는 따라가지 않습니다. macOS 메타데이터(`._*`, `.DS_Store`)도 제외합니다.
- 하위 범위가 겹치는 검사 폴더는 중복 등록할 수 없습니다. 기존 폴더의 하위 폴더 포함 옵션을 사용하세요.
- 파일 자체의 수정 시각과 내용은 보존합니다. 새 대상 파일의 생성 시각·접근 권한 등은 대상 파일 시스템의 동작을 따릅니다.

## 탐색기에서 규칙 추가

1. 새 `Chagok-v0.5.8.exe`를 사용할 위치에 두고 실행합니다. 이전 차곡이 트레이에 있으면 먼저 종료합니다.
2. 시작 시 현재 사용자의 메뉴 등록을 확인합니다. 수동 등록·해제는 `설정 → 탐색기 연동`에서 즉시 적용합니다. 자동 확인을 끌 수도 있습니다.
3. Windows 탐색기에서 이동 목적지로 쓸 폴더를 우클릭하고 `차곡에 추가`를 선택합니다. Windows 11에서는 `더 많은 옵션 표시` 안에 보일 수 있습니다.
4. 창에서 목적지를 확인하고 규칙을 넣을 기존 검사 폴더를 선택하거나 새 검사 폴더를 등록합니다. 다음 규칙 편집 창에서 조건을 정해 저장합니다. 파일을 바로 이동하지 않습니다.

EXE를 이동·교체해 경로가 달라지면 새 EXE에서 자동 확인 또는 메뉴 경로 갱신을 수행하세요. 해제는 같은 설정에서 합니다. 앱을 삭제하기 전 해제하면 메뉴가 남지 않습니다. 새 검사 폴더 등록은 별도로 저장되므로 뒤의 규칙 편집을 취소해도 그 검사 폴더는 유지됩니다. 앱이 작업 중이면 요청을 대기하며 최대 20개까지 받습니다.

등록 키는 현재 사용자의 `Software\Classes\Directory\shell\Chagok.AddRule`입니다. 다른 탐색기 메뉴는 변경하지 않습니다. 단일 EXE 배포는 유지하며, 메뉴 등록은 각 PC에서 한 번 수행합니다.

### Windows 11 첫 메뉴 테스트 연동

이 빌드에는 첫 메뉴용 `IExplorerCommand` 네이티브 DLL과 개발용 sparse package manifest가 포함됩니다. **x64 Windows 11에서 개발자 모드가 이미 켜져 있을 때** 시작 시 또는 메뉴 등록 버튼으로 테스트 등록합니다. 개발자 모드 설정은 사용자가 Windows에서 직접 결정하며 차곡은 이를 켜거나 인증서를 신뢰하도록 변경하지 않습니다. 일반 사용자에게 개발자 모드 없이 배포하려면 신뢰되는 인증서로 서명한 패키지 배포를 별도로 준비해야 합니다.

테스트 PC에서는 `설정 → 탐색기 연동 → Windows 개발자 설정 열기`로 Windows 설정을 확인한 뒤 메뉴 등록을 다시 누릅니다. 실제 첫 메뉴 표시·활성화·해제는 이 맥에서 검증하지 못했습니다. 메뉴가 보이지 않을 때 탐색기를 다시 열거나 재로그인이 필요할 수 있습니다. 기존 메뉴도 함께 유지합니다.

연동 리소스는 `%LOCALAPPDATA%\FileOrganizer\shell-extension`의 버전별 폴더에 풀립니다. 등록 상태와 EXE 경로는 차곡 전용 HKCU 키에 저장합니다. 해제는 패키지·레지스트리 등록을 제거합니다. 로딩 중인 DLL을 강제로 지우지 않으며 버전별 리소스 파일은 남을 수 있습니다. 이 저장소는 앱 검사에서 제외합니다.

## 프로그램 감지

폴더 설정과 개별 규칙에서 프로그램 실행·종료를 설정할 수 있습니다. 폴더 조건은 규칙의 실행 조건을 막는 선행 조건이 아니라 추가 실행 경로입니다. 폴더 조건이 맞으면 켜진 규칙을 모두 한 계획으로 검사하며, 파일명·확장자·하위 폴더·제외 경로와 첫 일치 규칙 순서를 유지합니다. 같은 이벤트가 규칙 조건에도 맞으면 중복 요청을 만들지 않습니다. 겹치는 경로 중 확인이 필요한 경우 전체 계획을 목록 확인 후 실행으로 처리합니다. 폴더 조건이 맞지 않는 다른 프로그램 이벤트에서는 기존처럼 해당 규칙만 동작합니다.

감지할 실제 `.exe` 파일의 전체 경로를 지정하세요. 런처·바로 가기와 실제 실행 프로세스가 다르면 실제 프로세스를 선택해야 합니다. 이미 실행 중인 프로그램을 등록한 경우에는 그 자체로 시작 작업을 실행하지 않습니다.

감지는 앱이 트레이에 실행 중이고 현재 로그인 세션에 있는 동안에만 동작합니다. 윈도우 로그인 시 자동 시작은 이번 버전에 포함하지 않습니다. 감지가 필요한 날에는 앱을 먼저 실행하세요.

WMI 이벤트 등록이 거부되면 250ms 간격의 확인 방식으로 전환하고 실행 기록에 ‘대체 감지’를 남깁니다. 표본 사이 실행본이 모두 교체된 재실행은 구분하지만, 표본 사이에 시작과 종료가 모두 끝나는 짧은 실행은 놓칠 수 있습니다. 처음부터 실행 중인 프로그램을 새 시작으로 처리하지 않으므로 차곡을 실행한 뒤 대상 프로그램을 새로 실행해 테스트하세요. 경로를 읽을 수 없는 PID는 종료로 단정하지 않으며, 전체 조회가 실패한 표본은 이전 상태를 유지합니다.

프로그램의 권한 차이, WMI 서비스 제한, 아주 빠른 실행·종료 때문에 실행 경로를 읽지 못하면 감지 요청을 만들지 못할 수 있습니다. 이 경우 상태 표시나 실행 기록을 확인하세요. 마지막 프로세스 종료가 파일 저장 완료를 보장하지 않으므로, 사용 중이거나 변경된 파일은 실행 과정에서 보류합니다.

## 데이터와 기록

`%LOCALAPPDATA%\FileOrganizer`에 저장합니다. `설정 → 앱 정보 → 데이터 폴더 열기`로 열 수 있습니다.

- `settings.json`: 폴더·규칙·폴더 실행 조건·테마·창 닫기·종료 확인. 저장 전 설정은 `settings.json.backup`에 보관합니다.
- `history.jsonl`: 작업 시작·성공·실패·원본 보존·감지 오류 기록. 화면에는 최근 500개를 표시합니다.
- `scan-cache/scan-.../plan.db`: 현재 검사 결과·선택 상태·충돌 계산을 위한 임시 저장소입니다. 다시 검사하거나 규칙 목록으로 돌아가거나 폴더·규칙 설정을 바꾸거나 앱을 정상 종료하면 삭제를 시도합니다. 창을 닫아 트레이에 숨긴 동안에는 현재 결과를 유지합니다. 비정상 종료 등으로 남은 캐시는 다음 검사 때 정리합니다. 이전 검사를 재개하거나 자동 실행하지 않습니다.

검사 결과가 많으면 임시 저장 공간과 디스크 읽기·쓰기가 늘어납니다. 임시 저장소 오류는 파일별 경고로 넘기지 않고 검사를 중단합니다. 실행 중 저장소·기록 오류가 발생하면 남은 이동을 중단하며, 이미 처리한 파일은 실행 기록에서 확인해야 합니다.

설정이 손상되면 덮어쓰지 않고 시작을 중단합니다. 파일을 별도로 보관한 뒤 백업 설정으로 복구할 수 있습니다. 설정과 기록에는 파일 경로가 들어 있으므로 외부에 공유할 때 개인 경로를 확인하세요.

## 개발 기준

코드·UI를 변경하기 전 `AGENTS.md`와 `docs/ui-spec.md`를 읽습니다. 기존 버그에서 확인한 테마·기본 선택 창·정렬·진행·완료 기준을 다음 작업에도 적용합니다. 실제 Windows 확인 절차는 `docs/windows-test-guide.md`, 수행 결과와 미검증 범위는 `docs/verification.md`에 기록합니다.

## 개발·빌드

소스는 .NET 10 / WPF로 작성했습니다. 맥에서도 핵심 로직 테스트와 윈도우 대상 빌드가 가능하지만 WPF 화면 실행은 윈도우에서 해야 합니다.

SDK가 설치된 개발 PC:

```sh
dotnet run --project tests/FileOrganizer.Checks/FileOrganizer.Checks.csproj
dotnet build src/FileOrganizer.Windows/FileOrganizer.Windows.csproj
dotnet publish src/FileOrganizer.Windows/FileOrganizer.Windows.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o dist/win-x64
```

ARM 윈도우용 빌드는 `-r win-arm64`로 지정합니다. 현재 전달 패키지는 `win-x64`입니다.

현재 맥 작업 환경에서는 프로젝트 내부 `scripts/dotnet.sh`가 SDK 위치를 읽습니다. 외장 드라이브의 메타데이터 문제를 피하려고 SDK와 NuGet 캐시는 `/private/tmp`에 두었습니다. 임시 폴더가 정리되면 SDK를 다시 준비하거나 설치한 SDK로 위 명령을 사용하세요.

```sh
FILEORGANIZER_BUILD_CACHE=/private/tmp/fileorganizer-build-cache bash scripts/dotnet.sh run --project tests/FileOrganizer.Checks/FileOrganizer.Checks.csproj
```

## 검증 상태

- 맥에서 핵심 로직 테스트와 윈도우 대상 빌드를 수행했습니다. 최종 결과는 `docs/verification.md`에 기록합니다.
- 윈도우 실제 UI, 트레이, WMI 감지, 휴지통, 파일 잠금·드라이브 분리 동작은 맥에서 실행 검증할 수 없습니다.
- 테스트 PC에서는 `docs/windows-test-guide.md` 순서로 확인하세요.

## 네이티브 탐색기 확장 빌드

`src/Chagok.ShellExtension`의 C++ 구현과 `scripts/build-shell-extension.sh`를 사용합니다. 검증한 도구는 Zig 0.13.0입니다. `CHAGOK_ZIG=/path/to/zig bash scripts/build-shell-extension.sh`로 x64 DLL을 먼저 만들고, 그 뒤 Windows 앱을 게시합니다. DLL과 manifest·이미지·라이선스 고지는 EXE 안에 포함됩니다. Native DLL 변경 중 Windows 앱을 동시에 빌드하지 않습니다.
