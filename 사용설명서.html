먼저 파일 복사본으로 규칙 하나를 시험해 보세요.

실행하면 파일 위치가 바뀝니다.

중요한 파일은 별도로 백업하세요. 차곡에는 앱 내부 되돌리기 기능이 없습니다. ‘검사 및 실행’으로 목록을 여는 단계와 실제 이동 버튼을 누르는 단계는 구분됩니다. 자동 실행을 선택한 프로그램 조건은 확인 없이 이동할 수 있습니다.

  1. Chagok-v0.5.6-win-x64.zip을 Windows PC의 쓰기 가능한 폴더에 압축 해제합니다.
  2. Chagok-v0.5.6.exe를 실행합니다. 이전 차곡이 실행 중이면 트레이 메뉴에서 먼저 종료합니다.
  3. 왼쪽 검사할 폴더 옆 ＋를 눌러 검사 폴더를 등록합니다.
  4. ＋ 규칙 추가에서 파일명 조건과 이동할 폴더를 지정하고 저장합니다.
  5. 규칙의 검사 및 실행을 눌러 대상 목록을 엽니다.
  6. 파일과 이동 위치를 확인한 뒤 선택한 항목을 실행합니다.

배포 파일에는 .NET 실행 환경이 포함되어 있습니다. 사용자 PC에 IDE나 .NET SDK를 설치할 필요는 없습니다. 현재 배포물은 Intel/AMD 64비트 Windows용이며, macOS 실행 앱은 아닙니다. 코드 서명이 없는 테스트 빌드입니다.

02

화면과 기본 원리

어디를 눌러야 할지 모를 때, 이 세 곳만 기억하세요.

  1. 왼쪽: 검사 폴더원본 위치 선택
  2. 가운데: 규칙 카드조건·이동 위치 설정
  3. 오른쪽 위: 설정테마·닫기 동작

한 파일은 위에서 처음 일치한 켜진 규칙 하나로 처리합니다.

화면별 역할과 규칙 순서 보기

차곡은 검사 폴더 → 규칙 → 파일 조건과 이동 동작 순서로 설정합니다. 검사 폴더 하나에 규칙을 여러 개 저장할 수 있습니다.

왼쪽: 검사할 폴더

검사 폴더를 선택하거나 추가합니다. 각 폴더의 겹친 사각형 아이콘은 복제입니다. 아래 ‘실행 기록’에서 지난 작업을 확인합니다.

가운데: 선택 폴더의 규칙

폴더 설정 아이콘, 규칙 추가, 폴더 전체 검사 버튼과 규칙 카드가 있습니다. 규칙 카드에는 켜짐/꺼짐·편집·검사 및 실행이 표시됩니다.

오른쪽 위: 테마와 설정

테마 아이콘에서 시스템·라이트·다크를 선택합니다. 기어 아이콘은 설정 창입니다. 버전과 데이터 폴더 열기는 설정에 있습니다.

검사 및 실행 화면

대상 파일, 예정 작업, 이동 위치와 결과를 표시합니다. 검사 후 확인하고 실행하며, 완료 요약도 같은 화면에 표시됩니다.

규칙의 순서가 결과를 결정합니다.

폴더 전체 검사에서는 켜진 규칙을 화면의 위쪽부터 판단합니다. 한 파일은 처음 일치한 규칙 하나로 처리합니다. 현재 규칙은 추가한 순서로 표시되며, 순서를 끌어서 바꾸는 기능은 없습니다.

개별 규칙의 검사 및 실행은 그 규칙 하나만 검사합니다. 따라서 여러 규칙이 겹치면 폴더 전체 검사와 개별 검사의 결과가 다를 수 있습니다.

03

검사 폴더 설정

검사 폴더는 파일을 가져올 원본 위치입니다.

  1. 왼쪽 ＋검사 폴더 추가
  2. 찾아보기원본 위치 선택
  3. 저장제외 폴더도 설정 가능

원본 폴더와 이동 목적지는 서로 다릅니다. 제외할 하위 폴더도 선택할 수 있습니다.

제외 폴더·수정·제거 방법 보기
  1. 왼쪽 ＋를 누릅니다.
  2. 표시 이름을 입력합니다. 예: 다운로드, 작업 자료.
  3. 검사할 폴더 → 찾아보기에서 Windows 기본 폴더 선택 창으로 원본 위치를 선택합니다. 경로를 직접 입력할 수도 있습니다.
  4. 필요하면 제외 폴더와 폴더 실행 조건을 설정합니다.
  5. 저장을 누릅니다.

검사에서 제외할 폴더

검사 폴더 안에서 건드리지 않을 하위 폴더를 지정합니다. 폴더 선택하여 추가로 선택하거나, 경로를 입력하고 경로 추가를 누릅니다. 표에는 폴더 이름과 전체 경로가 표시됩니다. 선택 후 선택 제거로 제외 목록에서 뺄 수 있습니다.

제외 경로는 해당 검사 폴더의 하위 폴더여야 합니다. 하위 폴더를 실제로 검사할지는 각 규칙의 하위 폴더도 검사 옵션이 결정합니다. 이동 목적지로 등록된 폴더는 검사에서 자동 제외합니다. 링크·연결 폴더는 따라가지 않습니다.

수정과 제거

폴더를 선택한 뒤 본문 오른쪽 위의 폴더+기어 아이콘을 누릅니다. 기존 설정을 수정하거나 폴더 제거를 선택합니다. 폴더 제거는 차곡에 등록한 설정과 그 규칙을 제거하는 동작이며, 실제 폴더를 삭제하는 동작은 아닙니다.

상하위 범위가 겹치는 검사 폴더는 중복 등록할 수 없습니다. 기존 검사 폴더와 규칙의 하위 폴더 옵션을 활용하세요. 폴더 실행 조건은 프로그램으로 자동 실행에서 설명합니다.

04

규칙 만들기

어떤 파일을 어디로 옮길지 정합니다.

  1. 규칙 추가이름·확장자 조건
  2. 이동할 폴더목적지·같은 이름 처리
  3. 규칙 저장처음에는 수동 실행

같은 이름 처리: 이름 변경 / 휴지통으로 보내고 교체 / 건너뛰기. 파일 내용 중복 검사는 아닙니다.

조건 예시·이름 충돌 옵션 보기

검사 폴더를 선택하고 ＋ 규칙 추가를 누릅니다. 규칙 이름을 정한 뒤 아래 항목을 설정하고 규칙 저장을 누릅니다.

파일을 고르는 조건
항목설정 방법과 예시
규칙 사용켜진 규칙만 검사에 포함됩니다. 규칙 카드의 스위치로도 바꿀 수 있습니다. 스위치를 켜는 것만으로 파일이 이동하지는 않습니다.
하위 폴더도 검사켜면 검사 폴더의 하위 폴더까지 검사합니다. 제외 경로는 건너뜁니다.
특정 단어 포함보고서를 입력하면 월간_보고서.pdf 등이 대상입니다.
특정 단어로 시작IMG_를 입력하면 IMG_001.jpg 등이 대상입니다.
파일명 패턴 일치*는 0개 이상의 문자, ?는 문자 하나입니다. report_??.pdf는 report_01.pdf와 일치하고 report_100.pdf와는 일치하지 않습니다.
파일명 제한 없음파일명은 제한하지 않습니다. 확장자만으로 분류할 때 사용할 수 있습니다.
확장자.pdf, .jpg처럼 쉼표로 구분합니다. 비우면 전체 확장자입니다.

파일명 조건과 확장자 조건을 모두 만족해야 합니다. 대소문자는 구분하지 않습니다. 파일명은 확장자를 포함한 전체 이름으로 비교합니다. 파일 내용은 검색하지 않습니다.

이동 동작 설정

이동할 폴더를 선택합니다. 다른 드라이브의 폴더도 지정할 수 있습니다. 폴더가 아직 없다면 경로를 직접 입력하고 대상 폴더가 없으면 자동 생성을 켭니다. 자동 생성을 끈 상태에서 목적지가 없으면 해당 항목은 보류됩니다.

이동 위치에 같은 이름이 있을 때
옵션동작
이름 변경 후 이동번호를 붙인 다른 이름으로 이동합니다. 기존 대상 파일은 유지합니다.
기존 파일을 휴지통으로 옮기고 교체기존 대상 파일을 Windows 휴지통으로 보낸 뒤 새 파일을 놓습니다. 휴지통 이동에 실패하면 영구 삭제로 대신 처리하지 않고 교체를 중단합니다.
건너뛰기같은 이름이 있으면 해당 파일을 이동하지 않습니다.
이름 충돌 처리와 내용 중복 정리는 다릅니다.

내용이 달라도 이름이 같으면 선택한 충돌 정책을 적용합니다. 이미지 유사도 비교, 파일 내용 비교로 중복을 찾아 삭제하는 기능은 없습니다. 목적지에 같은 이름의 폴더가 있으면 보류합니다.

처음에는 실행 방식 → 수동 실행으로 시험하세요. 기존 규칙은 카드의 편집에서 수정하거나 규칙 삭제로 제거합니다. 규칙 삭제는 설정을 제거하며 이미 이동한 파일을 되돌리지는 않습니다.

05

검사하고 실행하기

대상 목록을 확인한 다음에 실제 이동을 시작합니다.

  1. 검사 및 실행아직 이동하지 않음
  2. 목록·선택 확인모든 페이지에 적용
  3. 선택 N개 실행여기서 실제 이동

한 페이지는 100건입니다. 페이지를 바꿔도 선택이 유지되며, 실행은 전체 페이지의 선택 항목에 적용됩니다.

페이지 선택·취소 방법 보기
  1. 1 검사 시작폴더 전체 또는 규칙 하나
  2. 2 목록 확인파일·작업·이동 위치 확인
  3. 3 선택 후 실행실제 파일 이동 시작
  4. 4 결과 확인요약·파일별 결과·기록
  1. 폴더 전체 검사 및 실행 또는 개별 규칙의 검사 및 실행을 누릅니다.
  2. ‘파일 / 규칙’, ‘예정 작업’, ‘이동 위치 / 판단 이유’를 확인합니다. 검사 단계에서는 파일을 이동하지 않습니다.
  3. 각 행의 선택 상태를 확인합니다. 전체 결과의 실행 가능 항목 선택과 전체 선택 해제를 사용할 수 있습니다.
  4. 선택 개수와 이동 경로를 확인하고 하단 실행 버튼을 누릅니다. 선택 개수에 따라 선택 N개 실행처럼 표시됩니다. 기존 파일을 교체하는 수동 실행에는 별도 확인이 표시됩니다.
  5. 완료 후 같은 화면에서 결과를 확인합니다.
선택은 현재 페이지만의 선택이 아닙니다.

검사 결과는 100건씩 표시합니다. ‘이전’·‘다음’으로 페이지를 바꿔도 선택은 유지됩니다. 전체 선택과 실행은 모든 페이지의 선택 항목에 적용됩니다.

검사·이동 중 하단 취소를 누르면 안전하게 중단을 시도합니다. 완료된 이동은 되돌리지 않습니다. 실행이 끝났거나 폴더·규칙을 바꿨다면 다시 검사한 뒤 실행해야 합니다. 규칙 목록으로 돌아가면 현재 검사 목록은 폐기됩니다.

06

진행과 결과 읽기

완료 개수와 파일별 이유를 함께 확인하세요.

  1. 정상 완료목적지 파일 확인
  2. 확인 필요보류·실패 이유 확인
  3. 원본 보존원본·목적지 둘 다 확인

처리율 100%가 이동 성공 100%를 뜻하지는 않습니다.

상태별 의미·필요 공간 보기

검사 중에는 전체 대상 개수를 아직 모르므로 움직이는 진행 표시를 사용합니다. 이동 중에는 전체 파일 처리 개수·경과 시간·현재 파일의 복사 진행을 표시합니다. 복사 100% 이후에도 검증과 원본 삭제 단계가 남아 있을 수 있습니다.

완료 화면과 파일별 상태의 의미
상태의미와 다음 행동
정상 완료선택한 항목이 모두 완료된 경우입니다. 이동 목적지에서 파일을 확인하세요.
일부 항목 확인 필요보류·실패·원본 보존 등이 섞여 있습니다. 파일별 처리 결과와 이유를 읽으세요.
보류대상 폴더 없음, 검사 이후 파일 변경 등으로 이동하지 않았습니다. 이유를 해소한 뒤 다시 검사하세요.
건너뜀같은 이름 건너뛰기 등 정책에 따라 처리하지 않은 항목입니다.
원본 보존목적지 사본과 원본이 함께 남을 수 있습니다. 두 위치와 기록을 확인한 뒤 직접 정리하세요.
실패 / 오류 중단접근 권한·파일 사용 중·디스크·기록 저장 등의 오류가 발생했습니다. 이미 완료된 이동은 유지됩니다.
취소 / 미실행취소된 작업 또는 아직 시도하지 않은 항목입니다. 완료된 작업의 자동 복구를 뜻하지 않습니다.

‘처리 결과’ 열에서 파일별 상태를 확인하고 기록 보기로 상세 기록을 엽니다. 처리율 100%는 모든 파일의 이동 성공을 뜻하지 않습니다. 파일 이동은 끝났지만 결과 기록 저장이 실패할 수도 있으므로, 기록이 없다는 이유만으로 미실행이라고 단정하지 마세요.

파일 이동에 필요한 공간

차곡은 임시 복사 → 복사 검증 → 최종 위치 확정 → 원본 삭제 순서로 처리합니다. 같은 드라이브에서도 복사 공간이 필요합니다. 대상 드라이브에 여유 공간을 확보하고 작업 중 드라이브를 분리하지 마세요. 기존 파일 교체 후 후속 단계가 실패했다면 기존 파일은 휴지통에서도 확인해야 합니다.

07

프로그램으로 자동 실행

프로그램이 시작되거나 끝나면 검사를 시작합니다.

프로그램 시작 / 종료 감지등록한 실제 .exe가 기준
↓ 감지 후 처리 · 둘 중 하나 선택
목록 확인 후 실행대기 알림 → 목록 확인 → 직접 실행
저장된 조건으로 자동 실행조건에 맞으면 확인 없이 이동

차곡이 실행 중이어야 합니다. 창만 다시 여는 것은 새 프로그램 시작이 아닐 수 있습니다.

폴더/규칙 조건·감지 한계 보기

특정 프로그램이 시작되거나 종료될 때 검사를 시작할 수 있습니다. 폴더 설정과 개별 규칙에서 각각 지정합니다.

  1. 폴더 설정의 폴더 실행 방식 또는 규칙 편집의 실행 방식을 엽니다.
  2. 특정 프로그램 실행 시 또는 특정 프로그램 종료 시를 고릅니다.
  3. 찾아보기로 실제 실행되는 .exe를 선택합니다. Windows 기본 파일 선택 창을 사용합니다.
  4. 감지 후 처리를 선택하고 저장합니다.
  5. 차곡을 실행해 둔 상태에서 대상 프로그램을 새로 실행·종료해 시험합니다.

목록 확인 후 실행

감지 요청을 대기 목록에 표시합니다. ‘목록 확인’으로 검사 결과를 열고 선택 항목을 실행합니다. ‘무시’는 해당 대기 요청을 버립니다.

저장된 조건으로 자동 실행

감지되면 저장한 규칙으로 검사하고 실행 가능한 항목을 자동 처리합니다. 이동·교체 정책도 적용되므로 먼저 수동으로 시험하세요.

폴더 조건과 규칙 조건의 관계

감지된 조건검사 범위
폴더 조건이 일치그 폴더의 켜진 규칙 전체를 한 목록으로 검사합니다. 각 규칙의 파일명·확장자 조건과 첫 일치 순서는 유지합니다.
폴더 조건은 불일치, 규칙 조건만 일치해당 프로그램 조건에 맞는 켜진 규칙을 검사합니다.
폴더와 규칙 조건이 같은 이벤트에 일치해당 규칙을 중복 실행하지 않습니다. 폴더 조건 또는 그 이벤트에 함께 일치한 규칙 중 ‘목록 확인’이 있으면 전체 목록 확인을 우선합니다.

예를 들어 폴더를 ‘편집기 종료 시’로 설정하면 그 폴더의 수동 규칙도 함께 검사합니다. 폴더 조건은 규칙의 프로그램 조건을 통과해야 하는 선행 관문이 아니라, 검사를 시작하는 추가 경로입니다.

감지할 때 알아둘 점

  • 첫 실행본 시작·마지막 실행본 종료가 기준입니다. 같은 EXE가 여러 개 실행 중이면 추가 실행과 중간 종료는 새 이벤트로 처리하지 않습니다.
  • 대상 앱이 백그라운드에 남아 있으면 창을 다시 여는 것은 새 프로세스 시작이 아닐 수 있습니다.
  • 차곡이 감지를 시작할 때 이미 실행 중인 프로그램은 새 시작으로 알리지 않습니다.
  • 바로 가기가 가리키는 런처와 실제 프로그램이 다르면 실제 EXE 경로를 지정해야 합니다. 파일명만 같고 전체 경로가 다르면 일치시키지 않습니다.
  • 차곡이 실행 중인 현재 로그인 세션에서 감지합니다. 창을 닫아도 계속 감지하려면 백그라운드 실행을 선택하세요. Windows 로그인 시 차곡 자동 시작 기능은 없습니다.
  • 트레이 메뉴의 프로그램 감지 일시 중지를 켜면 감지를 멈추고 대기 요청도 해제합니다.
250ms 확인은 WMI 알림을 쓸 수 없을 때의 대체 방식입니다.

Windows의 프로그램 알림(WMI) 등록이 실패하면 지정한 프로그램의 상태를 0.25초마다 확인합니다. 파일 폴더 전체를 매번 검사하는 것은 아닙니다. 표본 사이에 시작과 종료가 모두 끝나는 짧은 실행은 놓칠 수 있습니다. 실제 CPU·메모리 사용량과 반응 시간은 PC에서 측정해야 합니다.

요청이 바로 실행되지 않을 때

편집 창·현재 작업·확인이 필요한 검사 목록이 있으면 새 요청은 대기합니다. 기존 확인 목록을 마치거나 규칙 목록으로 돌아가 대기를 해제하세요. 같은 규칙 집합의 반복 대기 요청은 합칩니다. 폴더·규칙 설정을 바꾸면 이전 대기 요청을 해제합니다.

08

폴더와 규칙 복제

비슷한 규칙을 다른 검사 폴더에도 적용할 때 사용합니다.

  1. 폴더 복제 아이콘설정·규칙 전체 복제
  2. 이름·원본 변경새 검사 폴더 지정
  3. 복제이동 목적지는 유지

원본 설정은 유지합니다. 복제 후 각 규칙의 이동 목적지를 꼭 확인하세요.

복제되는 설정 자세히 보기

비슷한 규칙을 다른 검사 폴더에도 적용할 때 사용합니다.

  1. 왼쪽 폴더 항목의 겹친 사각형 아이콘을 누릅니다.
  2. ‘검사 폴더 복제’ 창에 원본의 설정이 채워집니다. 새 표시 이름과 검사할 폴더를 지정합니다.
  3. 제외 폴더와 프로그램 실행 조건을 검토합니다.
  4. 복제를 누르면 새 폴더 설정과 모든 규칙이 저장됩니다.
이동 목적지도 원본 설정대로 복제됩니다.

다른 목적지로 옮기려면 복제 후 각 규칙을 편집하세요. 제외 경로는 새 검사 폴더의 같은 상대 위치로 재배치합니다. 원본 폴더·규칙은 바꾸지 않으며 실제 파일이나 폴더 내용을 복사하는 기능은 아닙니다.

09

탐색기에서 규칙 추가

우클릭한 폴더가 이동 목적지가 됩니다.

  1. 목적지 폴더 우클릭차곡에 추가
  2. 검사 폴더 선택파일을 가져올 원본
  3. 규칙 추가조건 설정 후 저장

우클릭만으로 이동하지 않습니다. Windows 11에서는 ‘더 많은 옵션 표시’ 안에 보일 수 있습니다.

메뉴 등록·해제·Windows 11 안내

Windows 탐색기에서 이동 목적지 폴더를 우클릭해 규칙 작성을 시작합니다.

  1. 차곡의 설정 → 탐색기 연동에서 등록 상태를 확인합니다. 필요하면 메뉴 등록 / 경로 갱신을 누릅니다.
  2. 탐색기에서 파일을 모을 목적지 폴더를 우클릭하고 차곡에 추가를 선택합니다.
  3. 시작 창에서 ‘이동할 폴더’를 확인합니다. 필요하면 다른 목적지로 변경할 수 있습니다.
  4. ‘규칙을 추가할 검사 폴더’에서 기존 원본 폴더를 고릅니다. 아래 작은 글자는 선택한 검사 폴더의 전체 경로입니다. 새 원본을 쓰려면 검사 폴더 새로 등록을 선택합니다.
  5. 규칙 추가를 누르고 다음 편집 창에서 파일 조건과 이동 동작을 저장합니다.

우클릭만으로 파일을 이동하지 않습니다. 새 검사 폴더 등록은 별도로 저장됩니다. 다음 규칙 편집을 취소해도 이미 등록한 검사 폴더는 유지됩니다. 차곡이 작업 중이거나 다른 편집 창이 열려 있으면 탐색기 요청은 대기합니다.

Windows 11 메뉴 위치

기존 메뉴는 더 많은 옵션 표시 안에 나타날 수 있습니다. 첫 우클릭 메뉴 연동은 x64 Windows 11에서 개발자 모드가 이미 켜진 경우의 테스트 기능입니다. 차곡이 개발자 모드나 인증서 신뢰 설정을 자동 변경하지는 않습니다. 일반 배포용 서명 패키지는 아직 준비되지 않았습니다.

메뉴 관리

  • 차곡 시작 시 탐색기 메뉴 확인·등록은 기본 켜짐입니다. 메뉴 누락이나 EXE 경로 변경을 확인합니다.
  • EXE를 다른 위치로 옮겼다면 새 위치에서 차곡을 켜거나 설정에서 경로를 갱신합니다.
  • 메뉴 해제는 즉시 적용되며 시작 시 자동 등록도 끄고 저장합니다. 설정 창을 취소해도 이 해제는 유지됩니다.
  • 차곡 파일을 삭제하기 전에 메뉴를 먼저 해제하세요. 메뉴 표시가 갱신되지 않으면 탐색기를 다시 열거나 재로그인 후 확인합니다.
10

테마·종료 설정

테마와 창의 X 버튼 동작을 바꿀 수 있습니다.

  1. 테마 아이콘시스템·라이트·다크
  2. 백그라운드 실행창을 닫아도 감지 유지
  3. 프로그램 종료감지도 함께 종료

트레이에서 완전히 종료하려면 트레이 메뉴의 ‘종료’를 선택하세요.

테마·종료 확인 설정 보기

테마 바꾸기

메인 오른쪽 위 테마 아이콘을 누르면 시스템(모니터)·라이트(해)·다크(달) 아이콘이 가로로 나타납니다. 마우스를 올리면 이름을 볼 수 있습니다. 원하는 아이콘을 누르면 적용됩니다. 설정 창의 테마 선택으로도 변경할 수 있습니다. 시스템은 Windows의 앱 모드를 따릅니다.

이 HTML 위쪽의 ‘설명서 테마’ 버튼은 문서의 표시만 바꿉니다. 차곡 앱의 테마 설정과 연결되지 않습니다. Windows 기본 폴더·파일 선택 창의 모양은 운영체제 동작을 따릅니다.

창의 X 버튼 동작

설정X 버튼을 누르면
창만 닫고 백그라운드에서 실행기본값입니다. 창을 숨기고 트레이에 남습니다. 프로그램 감지는 계속됩니다. 트레이 아이콘으로 다시 열 수 있습니다.
프로그램 종료차곡과 감지를 종료합니다. ‘종료하기 전에 확인창 표시’를 켤 수 있습니다. 확인 창에서 ‘다시 묻지 않기’를 선택하고 종료를 확정하면 다음 확인을 생략합니다.

기어 아이콘의 설정 → 창 닫기에서 선택하고 저장합니다. 확인 창을 다시 켜려면 설정에서 ‘종료하기 전에 확인창 표시’를 켭니다. 트레이 메뉴의 종료는 명시적으로 앱을 끝내는 동작입니다.

작업 중 종료를 요청하면 현재 작업을 안전하게 중단한 뒤 종료합니다. 이미 완료된 이동은 취소되지 않습니다.

11

기록·백업·업데이트

이동 결과는 실행 기록, 설정 백업은 데이터 폴더에서 확인합니다.

  1. 실행 기록행을 두 번 눌러 상세
  2. 설정 → 앱 정보데이터 폴더 열기
  3. 설정 백업차곡 종료 후 복사

설정·기록에는 파일 경로가 들어갑니다. 다른 사람에게 보내기 전 개인 정보를 확인하세요.

기록·설정 복원·업데이트 방법 보기

실행 기록 확인

메인 왼쪽 아래 실행 기록 또는 완료 화면의 기록 보기를 누릅니다. 화면에는 최근 500개 기록이 표시됩니다. 행을 두 번 누르면 시간·규칙·원본·대상·작업·결과·이유를 확인할 수 있습니다.

프로그램 감지 진단 기록
기록확인할 내용
대체 감지WMI 등록 실패와 상태 조회 방식으로의 전환을 알립니다. 전체 감지가 중단됐다는 뜻은 아닙니다.
감지됨이벤트를 받았다는 기록입니다. 추가·통합한 요청 개수와 편집 창·작업·확인 목록 대기 여부를 확인합니다. 이동 완료 기록과 다릅니다.
경로 확인같은 파일명이라도 등록 경로와 실제 프로세스 경로가 다르면 제외합니다. 기록의 두 경로를 비교해 대상 EXE를 다시 선택하세요.
실패경로 조회·감지·이동·기록 등의 오류 이유를 확인합니다. 규칙 이름과 작업 열도 함께 읽으세요.

데이터 저장 위치

설정 → 앱 정보 → 데이터 폴더 열기로 엽니다. 위치는 %LOCALAPPDATA%\FileOrganizer입니다. 앱 이름이 차곡이어도 호환성을 위해 이 폴더 이름을 사용합니다.

파일 / 폴더용도
settings.json검사 폴더·규칙·프로그램 조건·테마·닫기 설정 등을 저장합니다.
settings.json.backup설정 저장 전의 이전 설정입니다. 파일 내용 백업이나 모든 버전의 설정 이력은 아닙니다.
history.jsonl작업과 감지 기록입니다. 사용자 파일명과 경로가 들어갈 수 있습니다.
scan-cache검사 결과·선택·처리 결과의 임시 저장소입니다. 모든 결과를 메모리에 쌓지 않고 100건씩 읽습니다.
shell-extension탐색기 첫 메뉴의 버전별 연동 리소스입니다. 연동 해제 후에도 리소스가 남을 수 있습니다.

설정 백업과 복원

  1. 작업이 끝난 뒤 트레이 메뉴에서 차곡을 완전히 종료합니다.
  2. 데이터 폴더의 settings.json과 필요하면 history.jsonl을 별도 위치에 복사합니다.
  3. 설정 복원이 필요하면 기존 파일을 다른 이름으로 보관한 뒤 백업한 설정을 settings.json으로 복사하고 차곡을 실행합니다.

다른 PC로 옮겼다면 원본·목적지·프로그램 경로를 다시 확인하세요. 임시 검사 결과로 중단한 작업을 자동 재개하지는 않습니다. 앱 실행 중 데이터 파일을 직접 편집하거나 임시 저장소를 지우지 마세요.

새 버전으로 교체하기

  1. 현재 앱을 트레이에서 완전히 종료합니다.
  2. 새 배포 ZIP을 새 폴더에 압축 해제합니다.
  3. 새 Chagok-v0.5.6.exe를 실행하고 설정의 앱 정보에서 버전을 확인합니다.
  4. 기존 설정을 확인하고 탐색기 메뉴 경로를 갱신합니다. 자동 확인을 켰다면 시작 시 갱신을 시도합니다.

동일 Windows 사용자에서는 기존 데이터 폴더를 이어 사용합니다. EXE만 공유해도 받는 사람에게 내 폴더·규칙 설정이 자동으로 함께 전달되지는 않습니다.

12

문제 해결과 제한

증상에 맞는 항목만 펼쳐 보세요.

검사는 끝났는데 파일이 이동하지 않았어요.

수동 실행은 목록을 보여준 뒤 사용자가 선택 항목을 실행해야 합니다. 실행 가능 항목 수, 선택 개수, 파일별 판단 이유를 확인하세요. 꺼진 규칙, 확장자 조건, 제외 경로, 하위 폴더 옵션도 확인합니다.

프로그램을 켰는데 규칙이 실행되지 않아요.
  1. 차곡이 실행 중이고 감지 일시 중지가 꺼져 있는지 확인합니다.
  2. 폴더·규칙의 프로그램 경로와 시작/종료 조건을 확인합니다. 해당 폴더에 켜진 규칙이 있어야 합니다.
  3. 대상 앱을 완전히 종료한 뒤 새로 실행해 봅니다. 창을 닫는 것과 프로세스 종료는 다를 수 있습니다.
  4. ‘목록 확인 후 실행’이면 대기 배너의 ‘목록 확인’을 누릅니다. 편집 창이나 이전 확인 목록이 있으면 먼저 마칩니다.
  5. 실행 기록의 ‘감지됨’·‘대체 감지’·‘경로 확인’·실패 이유를 확인합니다. 런처 또는 버전 변경으로 실제 경로가 달라질 수 있습니다.

대체 방식은 표본 사이에 끝나는 짧은 실행을 놓칠 수 있습니다. 프로그램 종료 감지는 해당 앱이 모든 파일 저장을 끝냈다는 보장이 아닙니다.

권한 오류나 ‘원본 보존’이 표시돼요.

파일을 사용 중인 앱, 폴더 쓰기 권한, 드라이브 연결과 여유 공간을 확인하세요. 원본 보존이면 원본과 목적지에 파일이 함께 남을 수 있습니다. 두 위치와 기록을 먼저 확인하고 다시 검사하세요. 권한 문제를 숨기기 위해 보안 기능을 끄는 방식은 사용하지 마세요.

‘차곡에 추가’가 없거나 첫 우클릭 메뉴 등록이 실패해요.

설정의 탐색기 연동 상태를 보고 ‘메뉴 등록 / 경로 갱신’을 누릅니다. Windows 11에서는 ‘더 많은 옵션 표시’도 확인하세요. 첫 메뉴는 별도 테스트 연동이므로 기존 메뉴와 등록 상태가 다를 수 있습니다. 메뉴 등록 실패 기록의 원인을 확인하세요.

이동을 취소하거나 되돌리고 싶어요.

작업 중 ‘취소’는 남은 작업의 안전한 중단을 요청합니다. 이미 이동한 파일을 원위치로 돌리는 기능은 없습니다. 실행 기록을 기준으로 위치를 확인하고 직접 복구해야 합니다. 교체한 기존 대상 파일은 Windows 휴지통에서 확인하세요.

파일이 많으면 메모리가 계속 늘어나나요?

검사 목록과 결과는 임시 디스크 저장소에 보관하고 화면·실행에 필요한 항목을 나눠 읽습니다. 앱 전체 메모리 상한을 설정하는 기능은 없습니다. 파일 수가 많으면 검사 시간과 임시 저장 공간 사용량이 늘어납니다. Windows에서의 실제 최대 메모리·CPU 사용량은 아직 측정하지 않았습니다.

설정 파일이 손상돼 시작하지 못해요.

앱을 종료하고 데이터 폴더의 설정 파일을 별도로 보관하세요. 정상 백업이 있으면 기존 파일을 보존한 뒤 백업을 settings.json으로 복원할 수 있습니다. settings.json.backup도 이전 설정일 뿐 정상임이 보장되지는 않으므로 원본을 먼저 보존하세요.

미지원 기능·문제 보고 방법

현재 버전에 없는 기능

주·월 단위 예약 실행, 실시간 폴더 감시, 파일 내용 검색, 내용이 같은 파일·비슷한 사진을 찾는 중복 정리, 앱 내부 되돌리기, Windows 로그인 시 자동 시작, 설치된 앱 목록 선택 기능은 포함하지 않습니다.

문제를 전달할 때 함께 알려주세요.

설정의 버전, 문제가 난 시간, 폴더·규칙의 조건, 수동/자동 실행 여부, 실제 원본·대상 상태와 관련 실행 기록을 준비하세요. 공유 전 사용자명·개인 폴더·파일 경로 등 민감한 내용을 가리세요.

이 문서는 0.5.6의 구현과 프로젝트 문서를 기준으로 작성했습니다. Windows UI·탐색기 첫 메뉴·프로그램 감지에는 테스트 PC에서 재확인이 필요한 항목이 있습니다. 설명서의 제작이 해당 기능의 실행 검증을 뜻하지는 않습니다.

CLI·TUI로 사용하기

같은 설정을 터미널에서도 사용할 수 있습니다. 먼저 기존 GUI를 트레이에서 완전히 종료하세요.

  1. tui로 실행Chagok-v0.5.6.exe tui → 방향키 TUI
  2. 명령으로 검사scan → 파일 이동 없음
  3. 확인 후 실행run → 새 검사 후 승인

GUI·CLI·TUI 중 하나만 실행합니다. GUI가 트레이에 남아 있어도 다른 앱의 설정·파일 작업을 차단합니다.

명령·단축키·공유 설정 안내

PowerShell에서 실행

배포 ZIP을 압축 해제한 폴더에서 아래 명령을 사용합니다.

.\Chagok-v0.5.6.exe tui
.\Chagok-v0.5.6.exe help
.\Chagok-v0.5.6.exe help run --json
.\Chagok-v0.5.6.exe folders list
.\Chagok-v0.5.6.exe scan --folder 다운로드
.\Chagok-v0.5.6.exe run --folder 다운로드

scan은 이동하지 않습니다. run은 새로 검사한 모든 실행 가능 항목을 대상으로 확인을 받습니다. 자동화/JSON 실행은 --yes를 명시해야 합니다. 이전 scan의 계획을 이어 실행하지 않습니다.

TUI 키

F1/?: 기능 설명 · Tab: 폴더/규칙 영역 전환 · 방향키: 이동 · Enter: 선택 · F: 폴더 추가 · N: 규칙 추가 · E/D: 편집/제거 · C: 폴더 복제 · Space: 사용/선택 토글 · R: 영역과 무관하게 선택 규칙 검사 · A: 전체 검사 또는 전체 선택 · N/P: 미리보기 페이지 · I: 전체 경로 상세 · Esc: 돌아가기 · Q: 종료.

폴더·규칙 폼은 항목 선택 후 Enter/E로 편집하고, 선택값은 ←→로 바꿉니다. 입력창의 Esc 또는 /cancel + Enter는 해당 항목만 취소합니다. 빈 Enter는 기존 값 유지, /clear는 비우기입니다. 폼 목록에서 S로 검토한 뒤 Y로 저장합니다. 목록의 Esc는 전체 폼 취소입니다. 파일 경로는 직접 입력합니다. 실행 전 모든 페이지의 선택 개수·교체 개수를 확인합니다. 작업 중 Ctrl+C는 안전하게 중단한 뒤 앱을 종료하며, 완료한 이동은 되돌리지 않습니다.

설정 공유와 감지

기존 데이터 폴더의 설정·기록을 함께 사용합니다. 터미널에서 바꾼 GUI 설정은 다음 GUI 실행에 적용됩니다. TUI의 색은 호스트 터미널 기본색을 사용합니다. session.lock 파일이 남아 있는 것은 정상이며 직접 지우지 마세요.

Windows 프로그램 감지는 watch 명령 또는 TUI의 W 감지 화면이 열려 있는 동안 동작합니다. 일반 TUI 메뉴에서는 자동 감지하지 않습니다. 자동 모드는 파일을 확인 없이 이동할 수 있고, 확인 모드는 대기 요청을 Enter로 열어 검토합니다.

트레이·탐색기 연동은 GUI에서 관리합니다. 전체 명령과 환경별 제한은 배포물의 docs/terminal-guide.md에 있습니다.
